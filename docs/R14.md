# R14: the 0.2 security release

On October 10 we reviewed 0.1.1 as its own users: Claude ran a first install, read five days of its ledger, used the CLI and search, and went through seals, the witness and the sandbox attack by attack. A second reviewer read the public repository at the same commit without seeing those notes. The review is the Claude doc "Symbia v2 dogfood review"; the ledger holds its plan and result under `review.dogfood.2026-10-10.*`. It found 26 problems: four high and eight medium, mostly in the sandbox and in how seals are verified. Brian asked for each to be fixed in one security patch, with the patch notes saying openly what was found, how, and what changed. CHANGELOG.md has those notes, one entry per finding.

## Decisions

- Ship every breaking fix, not only the safe ones: sandboxed writes limited to the roots and temp, protected paths, `verify --witness` failing on `behind` and `not witnessed`, a token for `--allow-remote`, and `find` leaving out tool calls.
- Change the file format now (format 4) rather than later: salted record ids, hashed cost fields and evidence, a chain that starts from the session, and a signed, chained witness.
- Notes only: the findings go in the CHANGELOG, not GitHub security advisories.
- Versions read `X.Y.YYYYMMDDHHMMSS`, the release commit's UTC time. This release is 0.2.

## Left open

- A program a command builds itself talking to `launchd` over its socket (finding 7). Untested; in SECURITY.md.
- Lines cut from the end of a witness can't be seen from the witness alone. In SECURITY.md and the README.
- Findings 23, 24 and 26 are about use and vocabulary, not code; the CHANGELOG says why each is unchanged.
- The default root is still the whole home folder, now with a warning. Brian sets `roots` in his own `config.json`.
