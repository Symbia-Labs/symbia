# B3: file and shell tools

Goal: Symbia replaces Desktop Commander for Claude's work on this Mac, and every file read, edit and command lands in the chain. Read CLAUDE.md, docs/B1-REPORT.md, docs/B1-2-REPORT.md and this file. v1's path guard is at ~/symbia-stack/symbia-pathguard/src/index.ts (read-only reference).

## Tools (stdio and streamable HTTP, same as the B1 tools)

- `symbia_fs_read {path, offset?, limit?}` → text with 1-based line numbers. Caps: 2,000 lines and 256 KB per call; the reply says when it was cut and where to continue. Binary files are refused with their size and sha256.
- `symbia_fs_list {path, depth? (≤ 5), glob?}` → entries with type, size and mtime. Cap 1,000 entries, with a truncation flag.
- `symbia_fs_search {pattern, path, glob?, literal?, ignore_case?, context? (≤ 5), max_matches? (≤ 200)}` → matches with file, line and context. Use the ripgrep crates (`grep`, `ignore`), respect .gitignore, and stop at a 30 s deadline with partial results flagged.
- `symbia_fs_write {path, content, create_only?}` → writes atomically (temp file then rename). Reply: path, bytes, sha256 prefix.
- `symbia_fs_edit {path, old, new}` → one exact replacement. If `old` matches zero or several times, refuse and say how many. Atomic write. Reply: path, line of the change, sha256 before and after (prefixes).
- `symbia_exec {command, cwd, timeout_ms? (default 120,000, max 600,000)}` → runs `/bin/zsh -lc <command>` in its own process group. On timeout, kill the whole group and return what was captured. Reply: exit code (or `timeout`), duration, the last 8 KB of stdout and of stderr. The full output goes into the evidence folder by sha256 (`evidence/<sha256>`, with a row in `evidence`) and the reply names the digest so it can be read with `symbia_fs_read`.

## Path policy

- Allowed roots come from `$SYMBIA_HOME/config.json` (`{"roots": [...]}`); default is the user's home directory.
- Always denied, even inside a root: `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/Library/Keychains`, `~/Library/Application Support/Claude`, and `$SYMBIA_HOME/keys`.
- Resolve `..` lexically, then realpath the closest existing ancestor and re-check it against the realpath'd roots and the deny list (port v1's symlink defense).
- `symbia_exec` checks `cwd` against the same policy. It does not try to police the command's contents.

## Records

Every call writes a `tool_call` record on the `apocryphal` lane with body `{tool, args_digest, path?, cwd?, sha256_before?, sha256_after?, exit?, bytes_returned, truncated}`. Content itself is not stored in the record. `est_host_ms`/`est_chars` may be null; `host_ms` and `chars` are filled as in B1.
