| symbia_status | Session status | true | | | false |
| symbia_find | Find records | true | | | false |
| symbia_get | Get a record | true | | | false |
| symbia_fs_read | Read a file | true | | | false |
| symbia_fs_list | List a folder | true | | | false |
| symbia_fs_search | Search files | true | | | false |
| symbia_record | Write a record | false | false | false | false |

Add a test that lists the tools through the MCP layer and asserts each has a title and either readOnlyHint true or an explicit destructiveHint.

## 3. README.md (at the repository root)

Plain, present tense, American spelling, no marketing. Sections:

- What Symbia is (two or three sentences: a cryptographically signed, hash-chained record of the work AI agents do, with lanes that mark how far each result can be trusted; one Rust binary on SQLite; MCP over stdio and streamable HTTP).
- Build from source: Rust 1.91 or later, `cargo build --release`.
- Use with Claude: the full `claude_desktop_config.json` block (`{"mcpServers": {"symbia": {"command": "/absolute/path/to/symbia", "args": ["mcp"]}}}`) and the Claude Code command `claude mcp add --scope user symbia -- /absolute/path/to/symbia mcp`.
- Tools: a table of the 11 tools with one line each.
- Data and safety: where data lives (`SYMBIA_HOME` defaults), the path policy and deny list, the read-only data directory, key pinning, what `verify` checks.
- Privacy Policy: Symbia collects no telemetry and sends nothing over the network itself. All records, seals, keys and evidence stay in `SYMBIA_HOME` on the user's machine, kept until the user deletes them. Commands run through `symbia_exec` can reach the network like any shell command the user runs. No data is shared with Symbia Labs or third parties. Contact: hello@symbia-labs.com.
