# R8: threads

Every chat on the Claude desktop shares one `symbia mcp` process, and so one session and one chain. Nothing on a record says which conversation or agent wrote it. That breaks the first pillar ("an independent record") as soon as two agents are at work. The client can't be relied on to identify the chat: the stdio connection is shared, and nothing in the request is known to name the conversation. R8 adds a thread to every record, supplied by the caller, and a seal scoped to one thread that proves that thread's records and their place in the full chain, without revealing the other threads' content. Read CLAUDE.md, docs/R3.md, docs/R6.md and docs/R7-REPORT.md first. Keep every existing test passing.

## 1. The thread

- A thread is a name: 1 to 64 characters from `A-Z a-z 0-9 . _ : -`. The default is `main`.
- Every tool accepts an optional `thread` argument. The server takes it out of the arguments before the tool runs, so tool argument structs and `args_digest` are unchanged. `tools/list` shows `thread` on every tool: "Name of the conversation or agent making this call. Pass the same value on every call; default main."
- An invalid `thread` is refused before the tool runs, with `thread must be 1-64 characters from A-Z a-z 0-9 . _ : -`. The refusal is still recorded: a `tool_call` record in `main` with the tool name and the error.
- Every record a call writes carries the call's thread: `tool_call` records, `symbia_record` writes, and a job's end record (which takes the thread of the call that started the job). Records Symbia writes itself (`session.resumed`) go in `main`.
- When the request carries `_meta`, the `tool_call` record lists its key names (not values) as `client_meta_keys`. This is for discovery: if a client turns out to send a conversation id, a later round can use it.

## 2. File format 3

- `chain` gains `thread TEXT`, `thread_sha256 BLOB NOT NULL` (sha256 of the thread's UTF-8 name) and `row_digest BLOB` (set only in a thread seal, below). `file_meta` gains `thread TEXT` (set only in a thread seal). Index `chain (thread)`.
- Format 3 chain hash: `sha256(prev_hash || row_digest || at_ms as 8-byte big-endian || thread_sha256)`. The row digest is unchanged from format 2; the thread is bound by the chain hash.
- `FORMAT` becomes 3. New sessions are format 3. Format 1 and 2 seals still verify, unchanged. A format 1 or 2 session file is never resumed: `session::open` treats it as not resumable, with the reason `older file format`.

## 3. Reading by thread

- `symbia_find` gains `in_thread` (filter to one thread). Each hit gains `thread`.
- `symbia_get` returns the record's `thread`.
- `symbia_status` adds `thread` (the caller's), `threads` (up to 20, most recently written first: `{thread, records, last_seq}`) and `new_thread`, a fresh random name (`t-` and 8 hex digits) an agent can adopt when it starts.

## 4. Thread seals

- `symbia_seal` gains `in_thread`. Without it, the seal is the full seal, as today. With it:
  1. Refuse when the thread has no records.
  2. Copy the session with `VACUUM INTO` to `seals/<session>-<seq>.thread-<first 8 hex of thread_sha256>.sqlite`.
  3. In the copy, for every chain row of another thread, store its `row_digest`, set `thread` to NULL, and delete its record, links and full-text row. Delete evidence rows whose digest doesn't appear in a kept record's body. Set `file_meta.thread` and `retention = 'seal'`. `VACUUM` the copy so deleted content isn't left in free pages.
  4. Hash and sign as for a full seal. The sidecar gains `thread` (left out of full seals, so their sidecars are unchanged).
- A thread seal's chain head equals the full chain's head at the same seq.
- `last_seal` and seal-on-exit ignore thread seals.
- The reply: `{path, file_sha256, chain_seq, thread, records, withheld, verified}`.

## 5. Verify, format 3

For each chain row:

- **Record present:**
  - `thread` must be set, and `sha256(thread)` must equal `thread_sha256`.
  - In a thread seal, the thread must be the seal's.
  - The row digest is computed from the record as in format 2. The chain hash uses it.
- **Record absent:**
  - Allowed only in a thread seal, and only with `row_digest` set and `thread` NULL.
  - Its `thread_sha256` must differ from the seal thread's. Otherwise: `a record of thread <t> was withheld at seq <n>`.
  - The chain hash uses the stored digest.

Links from kept records to withheld local records are allowed: the target id must be a `record_id` on the chain. `Verified` gains `thread` and `withheld`. The CLI adds ` thread <t>: <n> records, <w> withheld` to its `ok` line for a thread seal.

## 6. Tests

- **Names:** valid names; empty, 65 characters and bad characters refused.
- **Store:**
  - A write records the thread and its digest, and the format 3 chain hash is laid out as above.
  - `get` shows the thread; `find` filters by `in_thread`; the thread summary is ordered and counted.
- **Tamper:** changing `chain.thread`, `chain.thread_sha256`, or moving a record to another thread fails verify. Resign so the check past the signature runs.
- **Thread seal:**
  - Two threads interleaved, one with a secret string in a body. The thread seal of the other thread verifies, with the right counts, and the same head as the full seal at that seq.
  - The secret's bytes appear nowhere in the file.
  - A kept record linking to a withheld one verifies.
  - Deleting a kept record fails. Withholding a record of the seal's own thread fails with the message above. Evidence rows are pruned.
- **Compatibility:**
  - The format 1 fixture still verifies.
  - A new `tests/fixtures/format2.*` (made by the R7 binary) verifies.
  - Resume skips a format 2 session with `older file format`.
- **MCP:**
  - `thread` appears on every tool in the tool list.
  - A call with `thread` puts its `tool_call` record in that thread; without it, in `main`.
  - An invalid thread is refused and recorded.
  - `symbia_record` honours `thread`. A job's end record takes its start's thread.
  - Status shows the threads and a `new_thread`.
  - `_meta` key names land in `client_meta_keys`.
- **Stdio end to end:** two threads interleaved, a thread seal, and `symbia verify` printing the thread line.
