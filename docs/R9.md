# R9: search and analytics

Agents and people need to find earlier work and see what it cost. Today `symbia_find` searches only the open session, by keyword, and nothing reports cost or prediction outcomes. Everything stays behind MCP; there is no dashboard. Read CLAUDE.md, docs/B1.md, docs/R8-REPORT.md and the "Retrieval" and "Cost and placement" sections of the v2 brief first. Keep every existing test passing.

## 1. The index

- `$SYMBIA_HOME/index.sqlite` is derived data: it can be deleted at any time and is rebuilt on the next search. It is never sealed, and it is not part of any chain.
- Sources: every `sessions/*.sqlite` and every full seal in `seals/` (thread seals are skipped; they are subsets). Sources are opened read-only. A record is indexed once per `(session, record id)`, wherever it was first seen.
- Per source, the index keeps the highest chain seq it has read, and a refresh reads only newer rows. Every format is read: format 1 and 2 files have no thread, so their records index as `main`.
- **A document per record:**
  - session, record id, seq, key, version, kind, lane, thread, at_ms;
  - the cost fields (`est_chars`, `chars`, `est_host_ms`, `host_ms`);
  - for a `tool_call` record, `tool` and `error`;
  - for a result, its verdicts (section 4);
  - the record's outgoing links;
  - its text: the key, then the body's string values in order, capped at 8,000 characters. For a `tool_call` record that cites `stdout_sha256` or `stderr_sha256`, the first 16 KB of each evidence file that is valid UTF-8 is appended.
- Full-text: an FTS5 table over the document text.
- A refresh runs at the start of every `scope: "all"` find and every report, bounded to 2 s. Whatever is left over waits for the next refresh. The reply then carries `index_behind: true`.

## 2. Vectors

- **Config `embed`, either form:**
  - `{"url": "http://127.0.0.1:8081/v1/embeddings", "model": "<name>"}`: an OpenAI-style embeddings endpoint. Loopback only: `127.0.0.1`, `::1` or `localhost`; anything else is refused at load.
  - `{"server": "/opt/homebrew/bin/llama-server", "model_path": "~/models/<file>.gguf"}`: Symbia starts the server itself on first use, as its own child process (not under the exec sandbox), on a free loopback port. The arguments are `--model <path> --embeddings --pooling mean --host 127.0.0.1 --port <port> --ctx-size 2048`. Symbia waits up to 60 s for `GET /health` to return 200, and kills the server when Symbia exits. Both paths are checked at load as for `exec_unsandboxed` programs.
- **How vectors are made and stored:**
  - Document text is embedded in batches of 32 and stored as little-endian f32 blobs with the model name and dimension. A model change makes the old vectors stale, and they are re-embedded.
  - A vector search embeds at most 256 missing documents per call before searching. The rest wait, and the reply carries `unembedded: <n>`.
- **Search.** Cosine similarity over the documents that pass the filters, computed in Rust (brute force). The top `limit` are returned.
- **Without `embed`:** `similar` is refused with `vector search needs "embed" in config.json`.

## 3. `symbia_find`

New arguments:

- `scope`: `"session"` (default: the open session, as today) or `"all"` (every indexed session and seal).
- `similar`: text for vector search.

Behaviour:

- With `query` and `similar` together, the two rankings are fused by reciprocal rank (k = 60).
- With `similar`, or with `scope: "all"`, the search runs on the index. A session-scope search with only keyword filters keeps today's path.
- Each hit carries `score`, and `session` when the scope is `"all"`.

Every `symbia_find` call now writes a `tool_call` record:

- `scope`;
- `query`, and `similar` (first 200 characters);
- the filters;
- the ids of the hits;
- `unembedded` and `index_behind` when set.

`symbia_get` is unchanged and not recorded.

## 4. `symbia_report`

New tool. It reports on the open session (default) or, with `scope: "all"`, on everything indexed.

**Arguments:**

- `since_ms` and `until_ms`;
- `in_thread`;
- `by`: `thread` (default), `tool`, `kind`, `model` or `day` (UTC date from `at_ms`).

**Reply:**

```json
{"scope": "...", "records": n, "sessions": n,
 "groups": [{"group": "...", "records": n, "tool_calls": n, "chars": n, "host_ms": n, "errors": n, "refused": n,
             "estimated": {"records": n, "chars_ratio": x, "host_ms_ratio": x}}],
 "predictions": {"records": n, "with_results": n, "open": n, "held": n, "broke": n},
 "index_behind": false}
```

**Field rules:**

- `refused`: tool_call errors starting with `refused` or `denied`.
- `estimated`: the records that carried an estimate.
  - `chars_ratio` = sum(actual) / sum(estimated) over those records, and the same for `host_ms_ratio`.
  - Leave a ratio out when the estimate sum is zero.
- `with_results`: predictions with an incoming `results_of` link from a result, in any indexed session.
- Verdicts are read from result bodies:
  - `"held": true|false` counts one verdict;
  - `"verdicts": {"<id>": "held" | "broke" | "<anything starting with held or broke>"}` counts one per entry;
  - `"predictions": {...}` maps the same way, as earlier result records used it.

Groups are sorted by records, descending, up to 50. The call is recorded as a `tool_call`.

## 5. Tests

- **Index:**
  - It builds from two session files and a full seal, without duplicates and skipping thread seals.
  - A refresh picks up only new rows.
  - Deleting `index.sqlite` rebuilds it.
  - Format 1 and 2 fixtures index as `main`.
  - Evidence text is searchable through its tool_call record.
  - Text extraction follows its order and caps.
- **Vectors, against an in-process fake embeddings server** (deterministic vectors):
  - batching, stored blobs, and re-embedding after a model change;
  - the per-call cap with `unembedded`;
  - cosine ranking;
  - RRF fusion;
  - the refusal without `embed`;
  - non-loopback URLs refused at load.
- **Spawn mode:** when `python3` is available, a fake server script checks the argument list, the `/health` wait and the kill on drop. Otherwise the test prints that it was skipped.
- **Find:**
  - `scope: "all"` finds a record in an earlier session and returns its session.
  - The `tool_call` record lists the hit ids.
  - Session scope behaves as before.
- **Report:**
  - Grouping by each `by`, with the counts, sums and ratios.
  - Refused calls.
  - Predictions open, resulted, held and broke in each body form.
  - `day` uses UTC.
  - A thread filter.
- **Stdio end to end:** two sessions (stop and restart with resume off), a find across both, and a report.
