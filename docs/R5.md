# R5: a logged exception to the exec deny list (stopgap for `gh`)

Since R3, `~/.config/gh` is on the deny list, so `gh` and `git` over HTTPS fail inside `symbia_exec` ("operation not permitted" on `~/.config/gh/config.yml`). Website deploys go through GitHub, so they are blocked. Brian chose a stopgap over a credential broker: a config setting that re-opens named deny-list entries for exec only, with every affected call logged. The proper fix (MCP Wallet holding the token) comes later. Read CLAUDE.md, docs/R3.md and docs/R4-REPORT.md first. Keep every existing test passing.

## 1. Config key `exec_unlock`

- `exec_unlock`: a list of deny-list entries, spelled exactly as in `DENY_IN_HOME` (for example `".config/gh"`). Default: empty. Config load fails on any value that is not a `DENY_IN_HOME` entry, so the key can't be used to open arbitrary paths. `$SYMBIA_HOME/keys` can never be unlocked.
- Effect, exec only: an unlocked entry is left out of the exec sandbox's deny rules, and in `exec_read: "home"` mode it is added to the read allowances (both spellings, plus metadata on its ancestors), so the command can read and write it.
- The file tools are unchanged: `symbia_fs_*` still refuse unlocked entries, because the point is to let a tool such as `gh` use its own config, not to let the agent read it directly.
- Logging: every `symbia_exec` call (and job start) made while `exec_unlock` is non-empty records `unlocked: [...]` in its `tool_call` body. `symbia_status` reports `exec_unlock`. The `symbia_exec` reply includes `unlocked` when set, so the agent and the transcript see it too.
- Startup: when `exec_unlock` is non-empty, write one line to stderr naming the unlocked entries.

## 2. Tests

- Config: `".config/gh"` accepted; `"Documents"`, `"/etc"`, `"keys"` and `"../.ssh"` refused at load.
- macOS sandbox, temp home: with `.config/gh/hosts.yml` present and `exec_unlock: [".config/gh"]`, exec `cat` of it succeeds and `.ssh/id_test` is still refused; without the key, the `cat` is refused as before. Run both in `"home"` and `"deny_list"` read modes.
- `symbia_fs_read` of the unlocked file is still refused.
- The record and the reply carry `unlocked`; a call made without the key carries no `unlocked` field.
