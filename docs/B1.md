# B1, part 1: the core over MCP stdio

Build the smallest v2 that can carry a real MAP run end to end. Read CLAUDE.md first and follow it.

## Deliver

1. **Workspace.** Cargo workspace with one binary crate, `symbia`, edition 2024, building on Rust 1.91 (Homebrew). Suggested crates: `rusqlite` (feature `bundled`), `ed25519-dalek`, `sha2`, `serde`, `serde_json`, `serde_jcs` or equivalent RFC 8785 canonicalizer, `rmcp` (the official Rust MCP SDK) with `tokio`, `tempfile` for tests. Check current versions on crates.io and pin them.

2. **Data directory.** `SYMBIA_HOME` env var; default `~/Library/Application Support/Symbia` on macOS and `$XDG_DATA_HOME/symbia` on Linux. Layout: `keys/`, `sessions/`, `seals/`.

3. **Schema.** One SQLite file per session at `sessions/<session-id>.sqlite`, WAL mode, STRICT tables:

```sql
CREATE TABLE file_meta (retention TEXT NOT NULL, expires_ms INTEGER, embed_runtime TEXT) STRICT;
CREATE TABLE chain (seq INTEGER PRIMARY KEY, prev_hash BLOB NOT NULL, hash BLOB NOT NULL, at_ms INTEGER NOT NULL, record_id TEXT) STRICT;
CREATE TABLE records (
  id TEXT PRIMARY KEY, key TEXT NOT NULL, version INTEGER NOT NULL, kind TEXT NOT NULL,
  lane TEXT NOT NULL, lane_reason TEXT NOT NULL, body BLOB NOT NULL, model TEXT NOT NULL,
  session TEXT NOT NULL, at_ms INTEGER NOT NULL, expires_ms INTEGER,
  est_host_ms INTEGER, est_chars INTEGER, host_ms INTEGER, chars INTEGER,
  UNIQUE (key, version)) STRICT;
CREATE TABLE links (from_id TEXT NOT NULL, to_id TEXT NOT NULL, rel TEXT NOT NULL) STRICT;
CREATE TABLE evidence (sha256 BLOB PRIMARY KEY, bytes INTEGER NOT NULL, media TEXT NOT NULL) STRICT;
```

   Plus an FTS5 table over key and body text for `symbia_find`. `body` holds JSON (JSONB if the bundled SQLite supports it, else text JSON; say which in the report). New session files start with `file_meta.retention = 'session'` and an `expires_ms` (default 24 h from creation).

4. **Records.** Kinds: `prediction`, `result`, `observation`, `claim`, `rejection`, `question_set`, `tool_call`, `promotion`. Lanes as in CLAUDE.md; `lane_reason` required. `version` is the next integer for that key within the file. `id` is the lowercase hex sha256 of the RFC 8785 JSON of `{key, version, kind, lane, body, model, session}`. Links rels: `results_of`, `revises`, `supersedes`, `cites`. Cost: `est_host_ms`, `est_chars` come from the caller at write; `host_ms` (measured handling time) and `chars` (length of the reply returned for that write) are filled by the binary.

5. **Chain.** Every record write appends a chain row in the same transaction. `hash = sha256(prev_hash || record_id_utf8 || at_ms as 8-byte big-endian)`; genesis `prev_hash` is 32 zero bytes.

6. **Device key.** ed25519, generated on first use at `keys/device.ed25519` with mode 0600.

7. **Seal.** `PRAGMA wal_checkpoint(TRUNCATE)`, then `VACUUM INTO seals/<session>-<chain_seq>.sqlite`, set `file_meta.retention = 'seal'` in the copy, compute the copy's sha256, and write `<same>.seal.json`: `{session, file_sha256, chain_head, chain_seq, public_key, signature, at_ms}`, where the signature covers `file_sha256 || chain_head`. Note: setting retention in the copy changes its bytes, so compute the sha256 after that write.

8. **Verify.** `symbia verify <sealed.sqlite>`: recompute the file sha256, check the signature from the sidecar, re-walk the chain from genesis and recompute every record id. Exit 0, or exit 1 with a one-line reason.

9. **MCP server.** `symbia mcp` serves stdio with rmcp. One process is one session. Tools:
   - `symbia_status` → build, retention, file path, chain seq, chain head prefix, last seal, public key prefix.
   - `symbia_record {key, kind, lane, lane_reason, body, model, est_host_ms?, est_chars?, links?: [{to_id, rel}]}` → `{id, version, seq, head}` (head = 12 hex chars).
   - `symbia_find {query?, kind?, lane?, key_prefix?, limit?}` (limit ≤ 50) → list of `{id, key, version, kind, lane}`.
   - `symbia_get {id}` or `{key, version?}` → the full record with its links.
   - `symbia_seal {}` → `{path, file_sha256 prefix, chain_seq, verified}`.

## Tests (at least)

- Record ids are deterministic and change when any covered field changes.
- Versions increment per key.
- Tampering with a row in a sealed copy makes `verify` fail with the right reason.
- Seal round-trip verifies.
- FTS find returns the expected records.
- The `symbia_record` reply is under 300 characters.
- `tests/map_e2e.rs`: through the tool layer, write a `prediction`, seal, write a `result` linked `results_of` to it, seal again; verify both seals and assert the prediction's chain seq is lower than the result's.

## Gate

`cargo test` green, clippy clean, `tests/map_e2e.rs` passing, `cargo build --release` producing `target/release/symbia`.

Streamable HTTP, session resume (S1), the v1 importer, the decider, file and shell tools, routines, retrieval, the MQTT broker, promotion.
